# 授权码指南（开发者）

本文档面向开发者，说明应用的授权机制、密钥管理与发码流程。普通用户只需要在应用内粘贴授权码即可。

> 本文档为五子棋版；象棋版的对应文档见 [chessboard/docs/license.md](https://github.com/zengsheng-git/chessboard/blob/master/docs/license.md)。

## 🔐 机制概述

- 授权采用 **Ed25519 非对称签名**，纯离线验证，无需服务器。
- 开发者持有**私钥**签发授权码；应用内内置**公钥**验签。没有私钥就无法伪造有效授权码。
- 一套密钥同时管理**五子棋（本应用 wzqlink）**与**象棋 / 揭棋**等产品，靠授权码中的产品编号区分。
- 授权码为**永久授权**（签发时可指定到期日，作为限时码使用，见下文）。

### 用户侧行为

| 状态 | 表现 |
|---|---|
| 首次安装 | 自动开始 **7 天全功能试用**（试用期内与已授权功能完全相同） |
| 试用结束未激活 | 引擎进入**小白档（免费）**：固定深度 1、关闭云库（后端强制，非前端遮挡），其余功能正常 |
| 粘贴有效授权码 | 立即解锁全部档位，**永久可用** |

授权状态存储在用户配置目录：`<data_dir>/wzqlink/license.json`（记录首次运行时间与已激活授权码）。

## 🔑 密钥管理（重要）

| 密钥 | 位置 | 说明 |
|---|---|---|
| 私钥 | 仓库根目录 `license-private.key` | **绝密、已 gitignore、必须异地备份**。丢失后本系列授权码再也无法签发，只能换新密钥对并发布新版应用 |
| 公钥 | `server/src/license.rs` 的 `PUBLIC_KEY` 常量 | 随应用分发，可公开 |

```powershell
# 生成新密钥对（仅在第一次或决定废弃旧密钥时执行）
cd server
cargo run --bin license-keygen -- genkey
# 输出: 私钥写入 license-private.key，公钥 hex 需手动填入 src/license.rs 的 PUBLIC_KEY
```

> ⚠️ 私钥文件请复制到密码管理器/加密网盘等安全位置备份，并确认 `git status` 中不出现它。

## 📨 签发授权码

```powershell
cd server
cargo run --bin license-keygen -- sign --key ../license-private.key --product 1 --name 客户名字
```

输出示例：

```
授权给: 客户名字 (象棋, 至 永久)
授权码:
2G0G20-000000-SSNNHF-MAZ5F7-JJMED2-5Q03W4-...
```

把授权码整段发给用户，用户在应用内（工具栏授权标签 / 配置抽屉底部 → 激活）粘贴激活。

### 参数说明

| 参数 | 取值 | 说明 |
|---|---|---|
| `--product` | `0` | 通用码（象棋 / 揭棋 / 五子棋都能激活） |
| | `1` | 仅象棋（xqlink） |
| | `2` | 仅揭棋（jieqilink） |
| | `3` | 仅五子棋（wzqlink） |
| `--name` | 任意文本（≤60 字节） | 授权给谁，激活后显示在应用内，便于对账 |
| `--expire` | `yyyymmdd` | **可省略**；省略 = 永久授权。限时码到期后验签直接判"已过期" |
| `--machine` | 设备码 | 预留字段，当前版本收到非空设备绑定码会拒绝激活 |

## 🧬 授权码格式（技术）

```
码文 = Base32(Crockford)( [payload长度 u8][payload][Ed25519签名 64B] )，每 6 字符一组 '-' 分隔
payload = [版本 u8=1][产品 u8][到期天数 u32 BE(0=永久)][名字长度 u8][名字 utf8][设备码长度 u8][设备码 utf8]
```

- Base32 使用 Crockford 字母表（无 I/L/O/U），粘贴时大小写不敏感，`I/L→1`、`O→0` 自动归一，`-` 与空格会被忽略。
- 产品不符、过期、被篡改的码在激活时分别得到明确错误提示（"此授权码不适用于本应用"/"此授权码已过期"/"授权码无效"）。
- 设备绑定（防一码多用）为预留设计：payload 已含 `machine` 字段，未来收紧验证无需变更码格式，旧码依然有效。

## ⚠️ 安全边界

- 本仓库**源码公开**，懂编译的人可以自行构建去除验证的版本。授权机制防的是"直接下载安装包的普通用户"，这是离线方案已知上限；若需更强保护需将仓库转私有或引入在线激活。
- 试用期的"首次运行时间"记录在本地文件，不做防系统时间回拨的强对抗（避免误伤真实用户）。
- 小白档（试用结束未授权）固定深度 1；小白档同时也是付费档位阶梯的最低档（新手=深度 2，往上至高级=深度 12）。
- 小白档（试用结束未授权）固定深度 1 并关闭云库；小白档同时也是付费档位阶梯的最低档（新手=深度 2，往上至高级=深度 12）。
- 相关文案已同步：README 许可声明不再表述"永久免费开源"；应用内授权弹窗含三态说明与微信联系方式。
